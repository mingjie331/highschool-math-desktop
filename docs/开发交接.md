# 开发交接 · 1.4.0

首次安装与启动见 [README](../README.md)，协作流程见 [CONTRIBUTING](../CONTRIBUTING.md)。已验证开发环境为 Windows x64、Python 3.13、Node.js 24；编辑保存、预览和导出需要 XeLaTeX 与 Windows 中文字体。

## 运行链路与修改入口

Electron 的 `desktop/main.cjs` 创建窗口和独立访问 token，运行 `.venv/Scripts/python.exe -m backend.runner`。后台选择本机动态端口，通过标准输出告知桌面层；退出应用会停止后台和编译任务。页面通过同源 HTTP 调用后台，通过 preload 暴露的受限 IPC 访问桌面能力。

- 分类、题目 CRUD、草稿、组卷：前端 `App.tsx`/`api.ts`，后台 `app.py`/`catalog.py`/`papers.py`。
- AI 导入与核对：前端 `AIWorkbench.tsx` 及相关组件，后台 `agent*.py`；远程调用集中于 `deepseek.py`。
- PDF/LaTeX：前端 `PdfViewer.tsx`，后台 `latex_service.py`/`compile_queue.py`，模板在 `resources/preamble.tex`。
- 本机密钥：`desktop/agent-secrets.cjs` 使用 Electron safeStorage。后台只在内存中持有用于请求的密钥，渲染层配置状态不返回已有密钥。

开发运行数据在项目 `runtime`，与正式安装数据隔离。新运行目录复制 627 题种子库及 87 张图；种子库保留历史结构，运行副本自动迁移至 schema 9。不要直接更新种子数据库来测试功能。

## 配置与依赖

依赖清单、两份 npm 锁文件与源码一同提交，使用 `npm ci`，不要为启动项目随意升级依赖。Python 基础依赖在 `requirements.txt`，构建环境在 `requirements-build.txt`。PDF.js 生成资源由 `prepare-assets.cjs` 从锁定依赖复制，第三方许可由 `collect_licenses.py` 收集。

| 设置 | 默认与用途 |
|---|---|
| `QD_HOME` | 后台运行数据根目录；默认项目 `runtime` |
| `QD_TEST_HOME` | 桌面层隔离运行根目录，仅用于测试 |
| `QD_RESOURCES` / `QD_FRONTEND` | 后台资源和构建后的前端；默认项目对应目录 |
| `XELATEX` | 未在应用设置指定路径时的编译器路径；否则从 PATH 检测 |
| `QD_TEST_MATERIALS` | 私有测试材料；默认 `.local/test-materials` |
| `QD_TEST_DATA` / `QD_TEST_SNAPSHOTS` | 私有候选数据、历史测试副本，仅按测试脚本需要指定 |
| `QD_TEST_OLD_APP` | 安装更新回归使用的旧应用隔离副本 |

DeepSeek 密钥通过本机应用设置填写，不使用共享密钥或 `.env`。运行数据和加密上下文不能上传或共享；换电脑需要重新填写密钥。

## 测试、数据库与发行

`npm test` 运行后端、前端逻辑、密钥/偏好测试并构建前端，不调用付费 API。`scripts/test.ps1 -Electron` 额外运行桌面、模拟 AI 与布局回归，缺少私有 PDF 材料的项目会记录跳过。真实 LaTeX 深度验证使用 `-RealLatex`；真实 AI 脚本不纳入默认回归。

数据库变更必须增加明确迁移，并测试旧运行库升级、草稿、题源、配图和组卷数据保留。高于程序支持版本的库应拒绝写入；迁移前需备份。种子库 SHA-256 固定为 `46079ba90cd104902d8051bb7835504ec975a35159a658e8449cadcafa0f81c5`，若将来确需更换种子，须同步维护清单和测试并单独评审。

`build.ps1` 重建前端、PyInstaller 后台和 Electron 包。`release-manifest.json` 统一维护源码与文档范围，源码 ZIP 和 Git 提交均排除私有数据及原始历史验收资料。`zip_sources.py` 只生成候选源包；`release_tools.py --publish` 才建立不可覆盖的发行目录。公开仓库验证摘要见 [公开交接验证](公开交接验证.md)，原始本机验收与恢复备份不上传。

迁移和更新工具具有实际文件操作，不属于开发初始化步骤。迁移需来源程序正常退出且目标不存在；更新需发行校验通过，保留数据配置，失败回滚。不要以个人日常安装作为测试目标。


## 1.4.0 多题库更新

题库名称可自定义，系统题库保留所有旧内容；新题库初始为空，复用学期/专题/考点框架。题目、草稿、AI 会话、组卷和导出按题库隔离。批量移动和复制由题库管理操作，移动需先处理编辑草稿。单个 PDF 可导入 35 页，每批仍最多识别 20 页，选择或取消不会删除材料。数据库 schema 9，回退需配套恢复迁移前数据库和旧程序。
